# Многопунктовый интерфейс: запуск и передача

Ветка feature/averkieva-data-ui. Основа API: 3dc7a60; при обновлении получен более свежий 375430b с лимитами груза по плечам. Прежний stash сохранён, не применялся. Серверные изменения пришли с веткой Екатерины; самостоятельно расчётные/серверные модули не менялись.

## Открыть

Из корня yana-planner:

```sh
source .venv/bin/activate
python -m flask --app yana_planner.web:create_app run --host 127.0.0.1 --port 5003
```

http://127.0.0.1:5003/static/multi-stop-ui.html

На главной добавлена ссылка «Многопунктовый рейс». Старый планировщик остаётся доступен. При смене версии Python-сервер нужно перезапустить: прежние процессы на 5001/5002 могут не знать нового API.

## Что работает

- 1–8 уникальных получателей, добавление/удаление, независимые порядки посещения и важности.
- Обязательные объёмы, сроки, длительности, окна; ручные времена каждого плеча и запреты движения. Общий запас и поступления, одно судно.
- Экономика с отдельными cost_terms: горизонт оплаты, три ставки, сборы, источник/статус. Пустые значения — null. При смене судна профиль ставок и сборы очищаются. Денежные суммы JS не считает.
- POST /api/multi-stop/plan, schema_version yana-multi-stop-request/1, search_seconds=2 на этап. cost_terms вынесены из scenario. Подписи требований сохраняются в scenario.route_reference.ui_metadata, не отправляются неизвестными полями верхнего уровня.
- Блокировка повторного submit и полей во время запроса, индикатор секунд, finally восстанавливает управление. Клиентский сетевой предел 90 с больше стандартного серверного вычислительного предела 30 с.
- HTTP 201 — сохранение, выполнение проверяется по result.goal_met. Невыполнимость и незавершённый поиск — отдельные нормальные результаты. 400/408/500 и сетевые ошибки не сбрасывают состояние формы; submitted_request не нужен для его удержания.
- Отчёт по снимку result.input: приёмки/сроки/остатки, важность, доказанность целей, график операций и ожидания, серверные компоненты стоимости. Известная часть не выдаётся за полную сумму.
- Ссылки из links: серверная страница, JSON и отдельная история. Собственное представление сохранённого результата: /static/multi-stop-ui.html?run=ID; оно делает GET /api/multi-stop/runs/ID, не повторяет POST. Условия редактируемой формы по умолчанию учебные; сохранённый отчёт подписан номером и строится по своему снимку.
- Шесть сохранённых примеров отдельно от нового расчёта. Ошибки транспорта в примерах — явно маркированные mock-ответы; success/missing-costs/infeasible получены модулем; search-limit получен с внедрённой остановкой решателя.

## Проверки

node tests/test_multi_stop_ui.mjs
python -m unittest discover -s tests -v
ruff check src tests
ruff format --check src tests

В браузере живого сервера проверены: POST учебной кампании, неполные расходы, сохранение невыполнимости с HTTP201/goal_met=false и ошибка 400 короткого горизонта оплаты без потери любого поля. Полная стоимость с явно введёнными четырьмя сборами проверяется отдельно. Контракт HTTP408 и клиентское прерывание проверяются mock transport; общий серверный тайм-аут покрыт тестами Екатерины. JS-валидация не заменяет серверную проверку допустимости.

## Ограничения

Общий флот, автоматическая перестановка пути, денежная оптимизация, фактические допуски судна не заявляются. Казачье/Кресты и Сайды — кандидаты, новые расстояния и приём НКТ в Сайды не подтверждены. Дополнительные учебные пункты 5–8 вымышлены, не новые населённые пункты Яны.

Не менялись web.py, service.py, multi_stop*.py, web_worker.py, storage и capabilities. В base.html добавлена только навигационная ссылка. Новые Jinja-шаблоны готовы, но отдельный серверный маршрут их рендеринга не требуется для работающего статического интерфейса. Серверные страницы истории/отчёта остаются базовыми; оформление этой формы применяется через ?run=ID. Поля нового leg_payload_limits не добавлены в редактор — это отдельное расширение, старые расчёты с такими ограничениями не загружаются в форму для неявного повторного расчёта.

## При переносе в ветку Екатерины

Дополнено отображение result.reason и departure_checks: остаток груза, лимит, результат и источник. Редактор лимитов пока отсутствует. В архиве нет упомянутого test_multi_recipient_form.mjs; доступен test_multi_stop_ui.mjs. Проверки старого черновика не заявляем.

При показе отчёта страница прокручивается к результату. При открытии по ?run=ID явно указано: форма выше содержит отдельный учебный пример, она не восстановлена из сохранённого расчёта.

### Проверено после интеграции

- 289 Python-тестов, Ruff check и format --check src/tests: успешно.
- Новый test_multi_stop_ui.mjs и 8 проверок test_route_package.mjs: успешно.
- Живой POST из формы: четыре получателя, приёмки 37/59/81/101 ч, готовность 145 ч; неизвестные сборы остались неизвестными.
- Слишком короткий горизонт оплаты: сообщение «минимум 145 ч», поля сохранены.
- Вместимость 599 т при сумме обязательных поставок 600 т: сохранён невыполнимый результат.

Временные номера расчётов относятся к локальной тестовой базе и не переносятся через Git. Интерфейс не добавляет распределение тоннажа, автоматический поиск порядка остановок или прогноз для произвольных точек.
