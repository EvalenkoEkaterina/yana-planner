# Расширение v2: проверка неодинаковых судов

9 ноября 2026. N00–N09 и их сроки сохранены без изменения. Предыдущий комплект сохранён отдельно. В frozen_inputs.json до запуска новых сочетаний зафиксирован полный факторный план из восьми сочетаний трёх факторов, каждый в двух состояниях:

| Фактор | Состояние 1 | Состояние 2 | Механизм |
|---|---|---|---|
| Полезная вместимость A/B | 400/400 т | 200/400 т | Отправление первого доступного малого судна может дробить груз |
| Времена хода A/B | Оба: 36 ч вверх / 24 ч обратно | A: 48/36 ч; B: 24/18 ч | Быстрый ресурс можно направлять на повторные рейсы, меняя распределение груза |
| Поступления | 1650 т в 0 ч | 825 т в 0 ч + 825 т в 120 ч | Разный момент накопления партии взаимодействует с выбором судна |

Погрузка/выгрузка по 8 ч, подготовка 6 ч; суда доступны с 0/48 ч. При разных временах полный оборот A = 106 ч, B = 64 ч. Значения **новые сценарные допущения**, а не характеристики названных реальных судов. Они выбраны до результата, чтобы проверить различия ресурсов в обе стороны относительно исходных времён. Исторические и аналоговые наблюдения не объявляются их прямым источником. R00/R01 повторяют контрольные N00/N01 и дают проверку воспроизводимости целей; их не считаем независимыми подтверждениями эффекта.

Перебираем все 2 × 2 × 2 = 8 сочетаний (R00–R07), включая контроль. Каждый — на прежних сроках 164/246/328/410 ч, с прежним возвратом до 492 ч. Итого 32 дополнительных пары. Не выбираем отдельные выигрышные сочетания вместо полной таблицы. Не добавляем вероятности и не считаем процент удачных тестов вероятностью успеха в работе.

## Что исправлено в выборе результата

В v1 ограниченная по времени третья ступень иногда оставляла план позже READY при одинаковых первых двух целях. Неверным был выбор сохраняемого плана, не его физическая допустимость. В v2 на всех ступенях сохраняется лучшее проверенное решение по порядку: больше тонн → меньше рейсов → более ранняя последняя приёмка. Для третьей ступени известный допустимый план даёт верхнюю границу времени. При лимите поиска он сохраняется. Входы прежних десяти сценариев не менялись.

Это исправление не гарантирует преимуществ перед READY. Допустимое решение без доказанной оптимальности остаётся лучшим найденным; статусы сохраняются. Первичный цель — тоннаж, второй критерий — число рейсов, третий — время; после просмотра результатов их не переставляем.

При окончательном прогоне сохранены лучшие допустимые кандидаты предыдущих запусков: seed_plans.json. Они независимо проверены с теми же входами, их соответствие конфигурации защищено контрольной суммой. При равенстве всех трёх целей прежний кандидат не заменяется произвольным. Это повторное использование уже найденных решений, не новые сведения о поступлении или условиях. Запуски с такими кандидатами нельзя выдавать за измерение скорости поиска «с нуля»; скорость алгоритма не является метрикой эксперимента.

## Дополнительные метрики, без изменения цели оптимизации

- Принято к сроку и недопоставка, т.
- Число рейсов.
- Последняя приёмка, ч от T0; сравнение времени при одинаковом объёме.
- Средний момент приёмки, взвешенный по тоннам: Σ(q × конец выгрузки) / Σq. Это время от единого T0, включая ожидание от начала сценария; не время чистого хода.
- Суммарная занятость судов, судно·ч: сумма полных оборотов выполненных рейсов, включая подготовку. Это ресурсная метрика, не денежные затраты.

Средний момент приёмки не был целью решателя и может ухудшиться даже при улучшении последней приёмки. Сохраняем обе стороны изменения. Частичные объёмы нельзя представлять как более быстрый способ выполнения всей задачи на 1650 т. Деньги не рассчитываются без отдельной модели затрат; опубликованные ставки НМЦ не превращаются в себестоимость рейса.
