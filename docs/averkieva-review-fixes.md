# Исправления после проверки лида

Исправлены два замечания к архиву:

1. `dispatcher.js / gather()` использует общую `normalizeLoading` из `route-package.js`. Без скорости нулевая/пустая подготовка исключается вместе с отсутствующей скоростью. Ненулевая подготовка без скорости отклоняется с понятным сообщением. При заданной скорости пустой `load_h` исключается. Проверка JSON в браузере и Python-импорт приводят эти поля к совместимому виду.
2. `route_import.py` сохраняет исходный порядок поступлений, строит соответствие индексов после стабильной сортировки и пересчитывает `event.arrival_index`. Проверка задержки относится к выбранной исходной партии. Исходный объект не изменяется; повторный импорт нормализованного пакета не меняет результат.

Добавлены регрессионные проверки: поступления [120, 0], одинаковые времена поступлений, повторный импорт, нулевая/ненулевая подготовка без скорости, пустая фиксированная длительность при заданной скорости.

Проверки: 108 Python-тестов, 8 JS-тестов; Ruff и проверка синтаксиса dispatcher.js прошли.

`service.py`, `web.py`, `web_worker.py` не менялись. Capabilities не включены. Подключение формы, сохранение источников и восстановление после ошибки остаются у Еваленко по последнему согласованию.

Получена frontend-api.md с описанием POST /api/plan в ветке коллеги. Это справочный контракт; подключение API в данной правке не выполнялось. Ранее предложенная передача через route_package_json не является обязательной схемой: при интеграции следует использовать согласованный реальный API.

Батагайский пример остаётся учебным. География не подтверждает спрос, наличие судов, длительности и тарифы. Числа сохранённых отчётов не менялись.
