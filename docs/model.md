# Математическая постановка и проверка

Кандидат рейса задаётся судном и целым часом начала погрузки. `x_i` - бинарный выбор, `q_i` - целые тонны, `q_i <= capacity_i*x_i`, `q_i >= x_i`. Нулевые рейсы исключены. Все времена пересчитываются из длительностей операций.

Три последовательные цели: максимум принятых тонн, минимум числа рейсов при фиксированном лучшем найденном объёме, минимум последней приёмки при фиксированных объёме и числе рейсов. У третьей цели есть переменная `z >= receipt_i*x_i`. При лимите времени сохраняется лучший независимо проверенный кандидат. Оптимальность поздней цели не доказывает раннюю, если ранний поиск был прерван.

Ресурс судна занят от начала погрузки до окончания подготовки. Погрузочный и приёмный причалы - единичные ресурсы. Интервалы полуоткрытые `[start,end)`: окончание одной операции допускает начало следующей в тот же час.

Источник: сумма погруженного к моменту не превышает начальный остаток и поступления к этому моменту. Поступление в тот же час доступно перед началом погрузки.

Приёмка: сумма прибывшего к моменту минус подтверждённый отбор не превышает исходную свободную вместимость. До каждого отбора сумма завершённых выгрузок должна покрывать суммарный отбор. Неизвестный/неподтверждённый отбор не освобождает ёмкость. Речь о запасе проекта, а не об неизвестном запасе других продуктов на базе.

Проверяющий модуль не импортирует расчёты кандидатов из оптимизатора. Он отдельно восстанавливает даты, конфликты и события, проверяет:

`источник + груз в перевозке + принятый запас + отбор = начальный остаток + поступления`

`свободная ёмкость + зарезервированная ёмкость + принятый запас = вместимость`

Груз, уже прибывший к причалу, до окончания выгрузки остаётся в перевозке и отдельно резервирует ёмкость. Резерв не прибавляется второй раз к массе.

Перепланирование сохраняет выбранные `x=1`, фиксированные `q` и времена всех начатых рейсов. Прошлые невыбранные отправления недоступны. Поступление разрешено менять только если оно ещё не произошло на момент объявления. Обоим методам событие раскрывается одновременно; их исходные истории могут различаться. Для чистого сравнения алгоритмов продолжения можно задавать одинаковый фиксированный префикс напрямую через API.

Новый запрет, который противоречит уже начатому рейсу, не исправляется переносом в прошлом: требуется вмешательство. Задержки поступления не дают права менять подготовку/обороты уже выбранных ресурсов.

Решатель: [scipy.optimize.milp / HiGHS](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html). Статус `0` означает доказанную оптимальность соответствующей ступени; `1` - лимит; `2` - несовместные ограничения. На каждой ступени может применяться отдельный лимит времени. При невозможности подтвердить допустимый план итог не выдаётся за нулевую доставку.
