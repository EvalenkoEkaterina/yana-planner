# Погрузка в зависимости от тоннажа

## Что настраивается

У судна два режима погрузки:

- Фиксированный: прежнее поле `load_h`, целые часы.
- По производительности: `load_rate_tph` (положительное число т/ч) и
  `load_setup_h` (неотрицательное целое время подготовки к каждой погрузке).

Если задана скорость, применяется:

```text
Время погрузки = load_setup_h + ceil(quantity_t / load_rate_tph)
```

Округление вверх относится к передаче груза. Подготовка уже задана в целых
часах. Без скорости действует старое `load_h`; при скорости оно не используется.
Если `load_setup_h` не указано, при заданной скорости оно равно нулю.
Подготовка к погрузке отличается от `prep_h` — подготовки после возвращения.
Обе занимают свой ресурс в соответствующей части оборота и входят в активность.

Пример **учебной** производительности 50 т/ч и подготовки 1 ч:

| Груз | Передача груза | Вся погрузка |
| --- | ---: | ---: |
| 20 т | ceil(0,4) = 1 ч | 2 ч |
| 50 т | 1 ч | 2 ч |
| 51 т | 2 ч | 3 ч |
| 500 т | 10 ч | 11 ч |

В часовой модели близкие тоннажи могут занимать одинаковое число часов.
Переход на минуты — отдельное изменение сетки, которого сейчас нет.
Скорость может быть дробной: например, 2,5 т/ч. В JSON десятичный разделитель —
точка. Форма сайта принимает точку; сервер также понимает запятую.

## Как учитывают методы

READY по-прежнему выбирает максимально допустимую партию для рассматриваемого
судна и часа. Вначале проверяет большие партии, затем более короткие варианты
погрузки. Он проверяет причалы и весь оборот с длительностью именно этой партии.

В MILP кандидат теперь дополнительно задаёт целое число часов погрузки.
Кандидат связан с точным интервалом тоннажа, который даёт эту длительность:

```text
Если скорость r, подготовка s, длительность погрузки d:
floor((d - s - 1) * r) + 1 <= q <= floor((d - s) * r)
```

Границы также ограничены вместимостью судна и календарём допустимой партии.
При `x=0` груз нулевой, при `x=1` он лежит внутри этого интервала. Нельзя выбрать
короткую погрузку и положить в неё больше топлива. Варианты одного старта
взаимно исключаются ограничением занятости судна. Нелинейного выражения q/r
в матрице нет: интервалы обеспечивают точную зависимость в текущей целочасовой
модели, без перебора каждой тонны отдельным рейсом.

Независимый валидатор пересчитывает длительность по выбранному тоннажу,
а не берёт готовую длительность из кандидата решателя. Проверяются общий
погрузочный причал, доступность судна, приёмка, возврат, подготовка, календарь
партии и остановки движения. Начатые рейсы при задержке сохраняют свой груз,
а значит, и длительность погрузки.

## Экономика

Активность H восстанавливается по фактическому обороту каждой партии.
В экономической цели коэффициент выбранного кандидата равен:

```text
F_i + h_candidate * (R_i - P_i)
```

`h_candidate` включает зависящую от партии погрузку. Он больше не обязан быть
одинаковым для всех рейсов судна. Независимая оценка стоимости использует
пересчитанные времена; тарифы и подтверждение их происхождения остаются
ответственностью экономического блока команды.

## Как пользоваться на сайте

В карточке каждого судна:

1. Указать вместимость и остальные длительности.
2. Ввести «Скорость погрузки, т/ч».
3. Указать «Подготовка к погрузке, ч» или оставить 0.
4. Запустить расчёт и посмотреть конец погрузки в расписании и на диаграмме.

Поле «Погрузка без скорости» действует только при пустой скорости. Кнопки
восстановления старых R03/задержки возвращают фиксированный режим, поэтому
исторические примеры не меняются автоматически. В исходных условиях и JSON
сохраняются скорость и подготовка. Длины полос на диаграмме используют реальные
расчётные времена. Новый режим работает и через JSON/CLI:

```sh
yana plan examples/loading-rate.json --deadline 20 --time-limit 2 --out outputs/loading-rate
```

500 т грузятся с 0 по 11 ч, затем приёмка завершается в 13 ч. Чтобы проверить
20 т, скопируйте JSON и измените `target_t` на 20. Это отдельный учебный расчёт,
не изменение исходного R03. В отчёт CLI включена модель погрузки каждого судна.

## Ограничения и контроль

- Нужна производительность погрузочной системы для сочетания судна и причала.
  Значение 50 т/ч не объявляется фактической характеристикой реальной техники.
- Скорость постоянна в пределах каждой погрузки. Совместное использование
  насосов, изменение скорости по времени и непрерывная подача топлива не
  моделируются.
- Весь груз рейса должен быть в наличии к началу погрузки.
- Длительность приёмки, ход, возврат и подготовка после возврата пока фиксированы.
  Зависимость разгрузки от тоннажа — отдельное расширение.
- Перебор длительностей увеличивает число кандидатов. Для одного расчёта
  действует предел 12000 кандидатов, затем выдаётся объяснение вместо тяжёлой
  матрицы. Общий предел сайта 30 с также сохраняется.
- Изменение погрузки может изменить преимущество методов. Старые числа нельзя
  переносить на новые параметры без пересчёта.

Проверки: ручные расчёты 20/500 т, точные границы и дробная скорость,
покрытие всех допустимых партий на малой сетке независимым валидатором,
ресурсные ограничения, экономическая цель, фиксация начатых рейсов и реальный
веб-запрос с сохранением входов и результата.
