## Исправлено

- Cost и sensitivity используют один выбор проверенного сравнения.
  После перепланирования берётся updated_input, а не прежние условия.
  Оба статуса должны быть valid_simulation, планы повторно проверяются,
  тоннаж и входы обоих методов сопоставляются. Разные объёмы отклоняются.
- Поддержаны текущий и старый форматы PR №1. По умолчанию используется after;
  --phase before выбирает исходную фазу. Недостающий исходный вход не выдумывается.
- Без горизонта run_sensitivity возвращает missing_cost_inputs вместо KeyError.
  Отсутствующие ставки сохраняются неизвестными. CLI cost возвращает код2,
  если для денежного итога не хватает входов.
- Отрицательный математический корень отдельно помечается как находящийся
  вне области неотрицательных ставок; допустимый порог остаётся null.
  Различаются равенство при любых ставках, отсутствие пересечения, нулевой
  и положительный пороги. Указано направление изменения преимущества.
- Исправлены некорректные типы billing_mode, проверка переполнения расходов,
  импорты и форматирование Ruff. Сетку ставок участницы не меняли.

Оплата всех часов внутри выбранного интервала ожидания, включая совпадение
с недоступностью, теперь явно названа сценарным допущением. Это не факт договора.
НМЦ не включается в эксплуатационные расходы; фактическая экономия неизвестна.
