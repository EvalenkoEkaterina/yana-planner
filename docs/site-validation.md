# Проверка сайта — 13 ноября 2026 года

Основа: опубликованная версия тимлида `8c1f6d7`, ветка `feature/evalenko-optimizer`. Исправления подготовлены отдельно в локальной ветке `codex/site-validation-fixes`. Экономика сохранена. Прежний эксперимент с оценкой конца сезона из другой рабочей копии сюда не переносился.

## Исправленные причины отсутствия результата

* «Минимум затрат» требует ставок. Ошибка теперь открывает карточку нужного судна и выделяет незаполненное поле. Добавлена явная загрузка ставок выбранного учебного примера по совпадающим ID; чужие ставки не переносятся.
* Отключение экономики одновременно возвращает стратегию «Минимум рейсов». Выбор стратегии стоимости включает экономику. На форме больше не остаётся сочетание «искать минимум затрат без тарифов».
* Задержка топлива и погодное событие взаимоисключаются, как требует текущий формат модели. Последний выбранный пользователем вид события выключает другой.
* Поздний ответ начальной загрузки R03 больше не может подменить метаданные уже выбранного другого направления. До загрузки набора запуск отключён.
* Общий бюджет поиска теперь согласован с ограничением серверного процесса. Проверенный план сохраняется при исчерпании бюджета поиска; доказательство оптимальности отдельно отмечается.
* В многопунктовой форме отсутствие подтверждения состава сборов открывает шаг экономики. Ошибка видна независимо от текущего шага; введённые условия сохраняются.
* API возвращает JSON для ненайденных адресов и неверного HTTP-метода. Чрезмерно большие целые числа обрабатываются как ошибка входа.

## Выполненные проверки

* Все сценарные JSON из `examples/` проверяются соответствующим валидатором: флота или многопунктового рейса. Проверяются обе сети и оба встроенных пакета направлений.
* Матрица из 36 сочетаний: стратегия рейсов/стоимости, с тарифами/без них, фиксированная/зависящая от тоннажа погрузка, обычный расчёт/задержка/погодное событие. Некорректное сочетание стоимости без тарифов проверяется отдельно как ошибка. Расписания повторно проверяются независимым валидатором; начатые рейсы после события сохраняются.
* Проверки переключателей охватывают 64 перехода между сочетаниями настроек. Дополнительно проверяются нулевые ставки, неизвестные значения, источники и привязка ошибки к полю.
* Полный комплект Python: 300 тестов. JavaScript: 18 тестов/наборов, включая проверки пакетов, многопунктового интерфейса, приоритетов и переключателей. Проверка синтаксиса обоих изменённых сценариев страницы и Ruff.
* Серверные проверки включают реальные рабочие процессы расчёта, сохранение и повторное открытие отчётов, оба расчётных API, речной граф, некорректные запросы, 404/405/413 и тайм-аут.

## Проверено в браузере

1. R03, стратегия стоимости, явно загруженные учебные ставки, подтверждение оплаты. Получен сохранённый расчёт №3: оба метода доставили 1650 т, READY — 873000 ₽, MILP — 774000 ₽. Поиск вернул допустимый план без заявления о полной оптимальности. Это результат сценарных ставок, не подтверждённая экономия перевозчика.
2. Смена на Усть-Куйга — Батагай, переключение стоимости и затем вида события, быстрый поиск. Получен расчёт №4: после задержки оба метода доставили 600 т; READY — 4 рейса, MILP — 3. Экономика была явно выключена и не подменена нулём.
3. Многопунктовый рейс четырёх получателей: получен и сохранён план №1 с приёмками на часах 37/59/81/101. Неизвестные сборы оставлены неизвестными, поэтому полная стоимость не объявлена известной.
4. Запущено сравнение с обратным порядком важности через API, сохранён план №2. В этом примере приёмки совпали; сайт показал отсутствие различий, а не выдуманное улучшение.

Номера относятся к локальной базе этой рабочей копии. Проверка покрывает перечисленные режимы и границы, а не все мыслимые числовые входы. Допустимая недопоставка, доказанная невыполнимость и ограничение поиска — отдельные результаты модели; они не считаются ошибкой сайта.

## Повторить проверки

Из папки проекта с активированным существующим окружением:

```sh
PYTHONPATH=src python -m unittest discover -s tests
ruff check src tests
ruff format --check src tests
node --test tests/test_planning_form_state.mjs tests/test_route_package.mjs tests/test_multi_stop_ui.mjs tests/test_multi_stop_priority_comparison.mjs
node --check src/yana_planner/static/dispatcher.js
node --check src/yana_planner/static/multi-stop-ui.js
```
