# Пересчёт материалов Ушановой: S0–S5

Материалы 771e803 из feature/ushanova-economics объединены с текущей веткой.
Сами внешние источники из нового исследования повторно не верифицировались;
ни одна опубликованная цена или топливная составляющая не подставлена вместо
согласованных сценарных ставок. Полные ставки не подтверждены перевозчиком.

Запуск: `python scripts/check_economics_sensitivity.py`. Вывод —
`output/economics-sensitivity/report.md`, results.json и базовый пакет/планы.
JSON включает фактические входы, исходные ставки, оплаченное время по судам,
привлечённые суда, компоненты и контрольные суммы файлов Лизы.

Два фиксированных плана итогового consolidation: READY 500 т, MILP 800 т;
по 2 рейса, оба судна используются, 170 судо-часов активности и 70 ожидания.
В обоих планах SIM-A доступно с 0 ч, SIM-B с 0 ч; горизонт 120 ч.
Текущие ставки из CSV Лизы: 25 000/1 000/500 ₽. Они именно использованы в контроле,
а не перенесены из другого кейса без проверки входов.

| Вариант | READY, ₽ | MILP, ₽ |
|---|---:|---:|
| S0 Контроль | 255000 | 255000 |
| S1 Активность ×2 | 425000 | 425000 |
| S2 Ожидание ×2 | 290000 | 290000 |
| S3 Ожидание равно активности | 290000 | 290000 |
| S4 Отдельный рейс ×2 | 305000 | 305000 |
| S5 Не привлекать судно без рейсов | 255000 | 255000 |

Это переоценка тех же расписаний, не повторная оптимизация стоимости. Первичный
приоритет объёма и рейсов сохранён. Множители — условный стресс-тест, не диапазон
рыночных тарифов. Вследствие одинаковых рейсов и часов этих двух планов изменение
ставок не изменяет разницу их расходов. При разных объёмах это не экономия на
одинаковой выполненной работе; одинаковая общая сумма не означает одинакового результата.

S5 — отдельная постоценка договора, а не режим общего MILP. Плата полностью
исключается только для судна с нулём рейсов, при условном отсутствии резервирования,
мобилизации и отмены. Все часы использованного судна от исходной доступности
оплачиваются. Для контроля логики S5 проверен также малый пример 400 т: 174000 →
138000 ₽ при исключении неиспользованного SIM-B; это сравнение схем оплаты,
не преимущество алгоритма. В итоговом 800/500 т исключать некого.

Пример fuel_component_scenario.json не включён в полные ставки и не прибавлен
сверху: так не создаётся повторное начисление ГСМ. Цена топлива из него не
подтверждает судовую бункеровку, а расходы в литрах — учебные. Для многопунктового
прототипа отдельно нужно определить плату за промежуточный заход и обработку,
а также считать занятость одного судна за весь рейс один раз.
