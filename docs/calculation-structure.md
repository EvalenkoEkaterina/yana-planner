# Как устроены расчёты Yana Planner

Расчёты находятся в `src/yana_planner/calculations/`. Страница собирает условия, сервер проверяет их и вызывает нужный расчёт. Математические модули не читают поля страницы и не отправляют HTTP-запросы.

| Папка | Что рассчитывается | Основные функции |
| --- | --- | --- |
| `fleet/timing.py` | Погрузка, движение, приёмка, возвращение и готовность | `_times` |
| `fleet/candidates.py` | Допустимые варианты отправления и загрузки | `build_candidates` |
| `fleet/ready.py` | Последовательный план READY | `ready`, `_validate_fixed` |
| `fleet/optimizer.py` | План MILP и сравнение с READY | `optimize`, `compare` |
| `fleet/goals.py` | Поиск срока выполнения обязательного объёма | `earliest_required_volume` |
| `fleet/vessel_selection.py` | Выбор одного судна для многопунктового рейса | `calculate_vessel_selection` |
| `finance/costs.py` | Расходы флота и сравнение стоимости | `resolve_cost_terms`, `cost`, `compare_cost` |
| `finance/multi_stop.py` | Расходы одного рейса с несколькими получателями | `price_voyage` |
| `finance/sensitivity.py` | Условные изменения ставок и схемы привлечения | `variant_terms`, `price_fixed_plan` |
| `routes/network.py` | Поиск пути по речной сети и сумма расстояний | `shortest_path`, `validate_route_graph` |
| `routes/voyage.py` | Расписание одного судна по получателям | `normalize`, `check_voyage`, `plan_multi_stop` |
| `constraints/events.py` | Задержка поставки или запрет движения, пересчёт будущей работы | `apply_event`, `replan`, `run_replanning` |
| `constraints/weather.py`, `constraints/route_weather.py` | Проверка погодных данных, покрытия и явных ограничений | `normalize`, `restrictions`, `assess_route_weather` |
| `constraints/risk.py` | Проверка сохранённого плана при изменении условий | `analyze_risks` |

Старые имена модулей, например `yana_planner.planning` и `yana_planner.economics`, сохранены как совместимые ссылки на новую реализацию. Они не содержат второй копии расчёта. Благодаря этому API, командная строка и существующие проверки используют одну математическую реализацию.

## Основные зависимости

При фиксированной погрузке: возвращение = начало погрузки + погрузка + ход с грузом + выгрузка + обратный ход. Готовность к следующему рейсу дополнительно включает подготовку.

При заданной скорости: погрузка = подготовка к погрузке + округлённое вверх значение `тонны / т·ч⁻¹`. Календарь ограничивает груз на всём гружёном участке. Движение не пересекается с интервалами запрета `[начало, конец)`.

READY выбирает допустимые отправления последовательно. MILP сначала максимизирует принятый объём, затем минимизирует рейсы или расходы — в зависимости от стратегии, затем время последней приёмки. После расчёта независимый модуль `validation.py` заново проверяет расписание, баланс топлива и ограничения. Он намеренно не использует генератор вариантов как доказательство правильности.

Расходы = число рейсов × отдельные расходы рейса + активные часы × ставка активности + оплачиваемое ожидание × ставка ожидания. Подготовка после возврата входит в активность. Ожидание = доступное оплачиваемое время − активность; оба вида часов не пересекаются. Деньги внутри расчёта учитываются в копейках. Отдельные сборы за заходы не должны повторять расходы других ставок.

## Время поиска и результат

Общий лимит веб-запроса — 30 секунд. Для однополучательного расчёта внутри процесса выделяется общий бюджет поиска 26 секунд, оставляя время на запуск, проверку и отчёт. Этот бюджет общий для этапов и пересчёта после события. Ранее каждый этап мог занимать 30 секунд, и внешний лимит обрывал процесс вместе с найденным планом.

При исчерпании бюджета математический модуль сохраняет проверенный допустимый вариант. Оптимальность такого результата не объявляется доказанной. Внешний предел процесса сохраняется на случай длительной подготовки или других сбоев; тайм-аут не означает доказанную невыполнимость.

## Границы проверки данных

Проверяется структура, типы, единицы, конечность чисел, обязательные значения, уникальность ID, интервалы, сроки, соответствие ставок флоту и привязка событий к нужной партии. Неизвестное не превращается в ноль. Приложение не подтверждает фактическую доступность реального судна, достоверность пользовательской ссылки или безопасность прохода.
