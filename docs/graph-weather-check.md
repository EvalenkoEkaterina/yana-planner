# Одна законченная проверка графа и погоды

Подключён модуль weather_feed из работы Кати (6e30df9), не вся её ветка.
Исправлены проверки координат, структуры записей и списка погодных ID.
Основной интерфейс, расчётные цели и проверки времени выпуска прогноза не менялись.

Из корня проекта:

```sh
source .venv/bin/activate
python scripts/check_graph_weather.py
```

Результаты: `output/graph-weather-check/report.html`, `package.json`, `weather.json`,
`results.json`. Всё выполняется офлайн на переданных данных; новые выгрузки и обучение
не нужны. Входная сеть и путь сохраняются в пакете, погода — в weather_assessment.

Проверено: путь Нижнеянск → Северный → Усть-Куйга, 324 км, участки yana-1400/1399.
Профиль исторического исходного ECMWF IFS охватывает 1–5 июля 2025, 120 часов,
две погодные точки. Согласование сегментов означает только явное сценарное
использование максимума двух точек для всего направления, не подтверждение
покрытия реки. Координаты реестра причалов не выводились и не подменяли координаты
погодных запросов. Время выпуска неизвестно, доступность при решении не подтверждена.

При пороге 8 м/с превышений нет: closures=[] при полном наборе. Поэтому погодное
событие не добавляется и не обходится запрет ядра на прогноз без времени выпуска.
Если часы отсутствуют, closures=null и статус insufficient_weather_data; Батагай
получает unsupported_weather_route. Режим as_of_decision на этих метаданных блокируется.

Для проверки расчётной связки создан отдельный учебный сценарий внутри погодного
периода: 400 т, поступление в час 0, приёмка до 100 ч, готовность до 120 ч; остальные
параметры флота заимствованы из учебного R03. READY и MILP приняли 400 т.
Это не реальная перевозка, не измерение выигрыша и не прогноз задержек.

Непустые запреты из исторического прогноза в этом опыте не передаются в движок:
автоматическое событийное перепланирование этой связкой ещё не проверено.
Для него нужен отдельный исторический протокол с сохранением статуса информации
либо прогноз с подтверждённым временем выпуска. Не переименовывать прогноз
в реанализ и не придумывать время выпуска ради прохождения валидации.

Сеть/маршрут выбираются автоматически в проверочном скрипте; кнопка автоматической
погоды в основной форме пока не добавлена. Полная ветка погодного UI не объединялась.
