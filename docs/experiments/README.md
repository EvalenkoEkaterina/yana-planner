# Эксперименты

Для отдельных событий используется R03: 1 650 т, приёмка до 328 ч, возврат до 492 ч. Время отсчитывается от общего начала сценария. Это учебные условия, не фактическое расписание навигации.

| Опыт | Вход / команда | Что проверяет | Материал |
|---|---|---|---|
| Контроль R03 | `examples/r03.json` | READY и MILP без обновления | [Команды](../guides/commands.md) |
| A1 | `examples/arrival_delay.json` | В 60 ч объявлен перенос поступления 120→168 ч | [Разбор](../guides/first-experiment.md) |
| A2 | `examples/vessel_unavailable.json` | В 60 ч объявлена недоступность SIM-A на [120,200) ч | [Контракт и результаты](vessel-unavailability.md) |
| A3 | `examples/payload_restriction.json` | В 60 ч объявлен предел 200 т на [120,168) ч | [Контракт и результаты](payload-restriction.md) |
| Конфликт A3 | `examples/payload_restriction_conflict.json` | Новое условие затрагивает начатый рейс | [Диагностика](payload-restriction.md#начатый-рейс-и-вмешательство) |
| Серия сроков | `yana sweep-deadlines` | Чувствительность к сроку | [Протокол](deadline-sweep.md) |
| Набор v2 | `examples/v2_suite.json` | Серия сценариев и контрольные планы | [Протокол v2](protocol-v2.md) |
| Экономика | `yana sensitivity` | Две схемы оплаты, ставки и пороги | [Команды](../guides/commands.md#экономика) |

A1/A2/A3 - внутренние названия, не номера кейсов. Эти события запускаются отдельно; последовательность сообщений пока не поддерживается.

## Правила сравнения

1. Сначала статус и тоннаж. `valid_simulation` не означает выполнение всей поставки или реальный допуск.
2. При разных объёмах сравнивается тоннаж; уменьшение рейсов не называется экономией выполнения той же задачи.
3. При равном объёме сравниваются рейсы, окончание, средняя приёмка, занятость и условные расходы. Компромиссы сохраняются.
4. Для каждой ступени MILP учитываются статус и разрыв оптимальности. При лимите времени планы могут различаться.
5. Сохраняются все заранее выбранные точки, включая отсутствие преимущества и конфликт.

Числа в документах относятся к сохранённым запускам. Новая сводка строится из результатов нового запуска; подстановка контрольных цифр вручную недопустима.
