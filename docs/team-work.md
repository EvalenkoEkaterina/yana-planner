# Работа команды в репозитории

Текущее ядро, импорт и один цикл перепланирования подготовлены с ChatGPT/Codex. Это не личные результаты участниц. Следующие изменения каждая выполняет в своей ветке, прикладывая тесты и пример результата.

| Направление | Файлы | Практический следующий шаг |
|---|---|---|
| Разработка | replanning.py, planning.py | Последовательность из двух задержек, сравнение одинакового зафиксированного прошлого, проверка отсутствия знания будущего |
| Гидрология/ограничения | domain.py, validation.py, planning.py | Три отдельных сценария ограничения партии/гружёного хода/возврата, точные граничные тесты и численное сравнение |
| Экономика | economics.py, costs.template.json | Выбрать прозрачную условную схему оплаты, обосновать диапазоны, рассчитать сетку 3×3 и порог выгоды при одинаковом объёме |
| Интеграция/паспорт | tests/, docs/, результаты команд | Лично повторить запуск, проверить балансы и сопоставимость, описать допущения и фактический вклад |

Пример локальной ветки: `git switch -c feature/replanning-two-events`. После изменений: `python -m unittest discover -s tests -v`. Коммит должен описывать изменение поведения, а в отчёте — входы и ограничения. Не переименовывать условные суда в реальные и не заменять неизвестные фактические данные нулями.

В CI настроен такой же запуск тестов, но облачный запуск ещё не происходил: репозиторий локальный. Проект пока не опубликован на GitHub. Добавлять реальные закрытые операционные сведения в публичную историю нельзя без отдельного решения команды; предусмотрена игнорируемая папка private_data/.
