# Архитектура и сущности

## Вход и результат

Вход: сценарий доставки с объёмом, поступлениями, судами, сроками, ёмкостью, отбором и календарём ограничений. Для адаптации отдельно поступает сообщение об изменении условий.

Выход: планы READY/MILP, независимые проверки, показатели доставки и файлы JSON/CSV/HTML. При конфликте нового условия с начатым рейсом возвращается `requires_intervention`; подтверждённый итог продолжения неизвестен.

## Сущности

| Сущность | Смысл | Основные модули |
|---|---|---|
| Сценарий | Объём, сроки, режим, исходные условия | `domain.py` |
| Судно | Доступность, партия, времена, интервалы недоступности | `domain.py`, `planning.py`, `validation.py` |
| Поступление | Появление топлива в источнике | `planning.py`, `validation.py` |
| Рейс | Судно, начало погрузки, тоннаж, полный оборот | `planning.py`, `validation.py` |
| Приёмка | Прибытие, резервирование, выгрузка, занятая ёмкость | `planning.py`, `validation.py` |
| Условие движения | Предел партии и остановки | `domain.py`, `planning.py`, `validation.py` |
| Событие | Новые сведения и момент их объявления | `replanning.py` |
| Проверка | Допустимость в сценарии, балансы, показатели | `validation.py` |
| Расходы | Ставки, схема оплаты, занятость, ожидание | `economics.py`, `sensitivity.py` |

## Поток расчёта

```text
JSON / поддерживаемый Excel
          ↓
проверка входного контракта
          ↓
READY и MILP
          ↓
независимое исполнение рейсов и балансы
          ↓
показатели → условная экономика → отчёт

новое сообщение → фиксация начатых рейсов
                → пересчёт будущих → повторная проверка
```

Календарь условий поступает готовым входом. ML-прогноз не подключён.

## Карта кода

Модули расположены в [src/yana_planner](../../src/yana_planner).

| Область | Файлы |
|---|---|
| Входы | `domain.py`, `excel_import.py` |
| Планирование | `planning.py` |
| Адаптация | `replanning.py` |
| Независимая проверка | `validation.py` |
| Экономика и выбор фазы сравнения | `economics.py`, `sensitivity.py`, `comparison.py` |
| Эксперименты | `experiments.py`, `deadline_sweep.py` |
| Представление и запуск | `io.py`, `cli.py`, `__main__.py` |
| Совместимость прежних работ | `online.py`, `compat.py` |

`online.py` сохраняет прежний API участницы; произвольная очередь событий там не реализована. Файла `conditions.py` пока нет; действующие преобразования календаря находятся в `replanning.py`.

## Границы ответственности

- Валидатор самостоятельно восстанавливает исполнение и не переиспользует проверку кандидатов оптимизатора.
- Экономика оценивает проверенные планы; текущий MILP не минимизирует стоимость.
- Сводка читает результаты проверки и не доказывает оптимальность.
- Пути `examples/` и `outputs_online/` сохраняются: от них зависят команды и совместимость.
- Код остаётся одним Python-пакетом с отдельными модулями. Документация группирует ответственность без изменения импортов.
