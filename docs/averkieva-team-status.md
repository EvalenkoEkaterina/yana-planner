# Сообщение Еваленко — фронт и второе направление

Катя, подготовила фронт и пакет данных в локальной feature/averkieva-data-ui. На GitHub пока не отправляла, поэтому удалённая ветка ещё не отражает эти изменения.

Схема размещения:
- Над формой — выбор независимого направления, источники и импорт JSON.
- Перед флотом — стратегия «Минимум рейсов / Минимум затрат», горизонт оплаты и подтверждение оплаты всего доступного флота.
- В карточке каждого судна — расходы на рейс, активный час и ожидание, происхождение и источник тарифа. Скорость погрузки, подготовка к погрузке и подготовка после возврата сохранены отдельными полями.
- После поступлений — погодное событие: интервалы, час объявления, источник, synthetic/reanalysis/forecast, дата выпуска и T0 с часовым поясом.
- В результате — общая стоимость, три составляющие, разбивка по судам и статусы. Нет данных — не показываю нулевую стоимость; разность затрат — только при равном объёме.

Из существующих файлов меняю (пути относительно src/yana_planner/):
- templates/index.html
- templates/base.html
- templates/conditions.html
- templates/result.html
- static/conditions.js
- static/style.css

Добавляю частичные шаблоны route_setup.html, economy_setup.html, vessel_rates.html, weather_setup.html, cost_result.html; static/dispatcher.js, static/route-package.js и static/data/*.json. Проверку пакета вынесла в отдельный route_import.py; добавлены примеры, скрипты воспроизведения, тесты и документация. Новых зависимостей нет.

service.py, web.py, web_worker.py, оптимизатор и экономический модуль не меняла. Контракты сверены с edb5566 твоей ветки. Поля погрузки перенесены из твоего шаблона; при объединении важно не продублировать их.

До твоего подключения к серверу новые настройки проверяются и экспортируются как yana-route/1. Их запуск на старом сервере блокируется — иначе он мог бы молча рассчитать R03 без выбранной экономики/погоды. Старый R03 без новых настроек продолжает работать. Предложение передачи route_package_json и capabilities описано в docs/averkieva-front-integration.md; это предложение интеграции, не существующий HTTP API.

По расширению: добавлено независимое Усть-Куйга → Батагай, без общих судов с R03. Есть официальная разбивка 280+103 км и исторические свидетельства работы плеча у ЛОРП. Спрос, суда, длительности и партия в новом примере явно сценарные. Контроль: 600/600 т; READY 4 рейса, приёмка 186 ч; MILP 3 рейса, 180 ч. Оценка готовых расписаний по предложенным Лизой ставкам: 751 000 / 685 500 ₽. Это не денежная оптимизация и не фактическая экономия. В сохранённом контрольном запуске все этапы оптимальны.

Есть опыты со сроком, пределом партии, статическим запретом и задержкой поступления. Погодный JSON соответствует твоему договору; реальный прогноз не загружен и его точность не заявляется.

Проверки: 108 Python-тестов, 8 JS-тестов импорта, Ruff; браузером проверены выбор маршрута, экспорт, ошибка дубликата ID с сохранением формы и корректный импорт. Вёрстка проверена на 1280 и 390 px.
