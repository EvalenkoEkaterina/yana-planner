# Интерфейс Аверкиевой v2 подключён к серверу

Статус: 13.11.2026, ветка feature/evalenko-optimizer. Приняты файлы из
averkieva-lead-review-v2.zip с исправлениями нормализации погрузки и индекса
поступления. Серверная интеграция выполнена Еваленко поверх актуального ядра.

## Что работает

- Выбор R03 или независимого Усть-Куйга — Батагай, импорт/экспорт yana-route/1.
- Форма передаёт route_package_json через POST /; старые клиенты формы остаются
  совместимы. В web_worker пакет импортируется, затем calculate_package
  вызывает тот же calculate_request, что и POST /api/plan.
- До расчёта сервер проверяет полный пакет, стратегию, тарифы и событие.
- Индивидуальные ставки, общий оплачиваемый горизонт, выбор trips/cost.
- Погрузка с производительностью и два разных вида подготовки.
- Явная задержка поступления или явное погодное событие, по одному за опыт.
- Общий 30-секундный бюджет процесса применяется к этому пути тоже.
- В SQL сохраняются route/sources/facts и полный нормализованный пакет,
  сценарий, событие, стратегия, тарифы и версия расчётного кода.
- После серверной ошибки или тайм-аута восстанавливается полный пакет:
  маршрут, суда, тарифы, горизонт, событие, T0 и подтверждение оплаты.
- На странице и в HTML-отчёте доступны источники и статусы происхождения.
- capabilities включены после подключения обработчика и сквозной проверки.

Погодная прогнозная модель не подключена и не требуется для этих проверок.
Погодный интерфейс принимает подготовленное событие. Синтетический интервал
не обозначается реальной погодой или прогнозом.

## Исправления при интеграции

Взяты обе поправки Нади v2 и регрессионные тесты: подготовка только вместе
со скоростью, пустой load_h исключается, индекс задержки сохраняет выбранную
партию после сортировки. В API-адаптере также сохранена связь индекса с исходным
порядком. Повторная нормализация уже упорядоченного пакета не меняет партию.

Дополнительно сохранены выбранный маршрут и источники после ошибки, исправлено
восстановление отметки оплаты и очистка T0 при удалении значения из формы.
При ошибке поиска метаданные пакета не теряются. Старые расчёты без пакета
продолжают открываться.

## Подтверждённые проверки

- 211 Python-тестов; 8 JS-тестов импорта/нормализации.
- Ruff проверка кода и форматирования.
- Через настоящий браузер: R03, preset задержки, Батагай с денежной целью,
  серверная ошибка малого горизонта оплаты и восстановление, история маршрутов.
- На экране 390 px: форма и результат; ширина документа равна ширине экрана,
  таблицы прокручиваются внутри контейнеров.
- Снимки проверки находятся локально в output/interface-check/.

В контрольном браузерном запуске R03: 1650 т, MILP 5 рейсов, последняя приёмка
224 ч. Это результат учебного примера. В денежном опыте Батагая: 600 т,
3 рейса, последняя приёмка 258 ч, сценарные затраты 664500 руб. Другой выбор
цели даёт другой результат, чем сохранённый пример минимума рейсов.
Эти числа не являются доказательством фактической экономии.

## Как обновиться

```sh
git fetch origin
git switch feature/evalenko-optimizer
git pull --ff-only origin feature/evalenko-optimizer
source .venv/bin/activate
python -m flask --app yana_planner.web:create_app run --port 5001
```

Адрес: http://127.0.0.1:5001 . Если сервер уже работал, остановить именно
свой процесс через Ctrl+C и запустить снова: изменение Python-файлов без
режима автоперезагрузки не подхватывается автоматически. Изменение фронта
при необходимости проверить после обновления страницы без кеша.

Старые указания архива «capabilities не включать» описывают состояние пакета
до интеграции. Текущее состояние определяет этот документ. Погодный конвертер,
реальные эксплуатационные входы и финансовая валидация остаются отдельными
задачами; Батагайский профиль по-прежнему учебный.
