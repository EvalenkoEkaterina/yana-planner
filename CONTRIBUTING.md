# Совместная работа

## Перед началом

Прочитайте [актуальные задачи](docs/team/README.md) и [статус ТЗ](docs/specs/README.md). Убедитесь, что работаете с согласованной версией: ветка `main`, рабочая ветка и выпуск первой сдачи могут различаться.

Создавайте ветку от согласованной основы. Имена: `feature/описание`, `fix/описание`, `docs/описание`. Одна ветка решает одну понятную задачу.

## Куда класть материалы

| Материал | Место |
|---|---|
| Расчётная логика и общие функции | `src/yana_planner/` |
| Проверки поведения и границ | `tests/` |
| Небольшие воспроизводимые входы | `examples/` |
| Математика и архитектура | `docs/model/` |
| Происхождение данных | `docs/data/` |
| Условия и выводы эксперимента | `docs/experiments/` |
| Инструкции | `docs/guides/` |
| Актуальные задания | `docs/team/tasks/` |
| Прошлые протоколы | `docs/archive/` |
| Результаты локального запуска | `outputs/`, не включать в Git |

Сценарные числа помечаются явно. Неизвестные значения не заменяются нулями. Не добавляйте закрытые сведения, ключи или персональные выгрузки; для локальных закрытых данных предусмотрено `private_data/`.

## Перед Pull Request

1. Проверить [тесты и стиль](docs/quality/checks.md).
2. Обновить затронутые команды, ссылки и ограничения в документации.
3. Приложить краткое описание: проблема, новое поведение, команда повторения и результаты проверки.
4. Указать изменение формата, зависимостей или общих модулей, если оно есть. Условный экономический эффект не выдавать за фактический.

Общие контракты, CLI и независимый валидатор согласуются до объединения. Объединение в основную ветку - отдельный этап после проверки комплекта.
